# Weeknote

**把一周的零散记录，整理成可修改、可导出的周报。**

到了周五，这周的工作还散在随手记的几句话、会议文档和几张截图里。写周报，要先把材料找齐，再理清进展，最后调整成需要的格式。

Weeknote 帮你把这些材料整理成初稿：输入笔记、上传附件，按模板生成内容，再通过对话补充和修改，确认后导出 Word。已有固定的汇报结构，也可以提供几份样例，让 AI 归纳成可复用的模板。

Weeknote 是一个自托管网页应用，使用 DeepSeek 整理内容，周报和模板保存在部署机器的 SQLite 中。

## 使用示例

### 从几句记录开始

不用先把材料写成完整的周报。几句工作记录，就可以作为整理的起点：

> 修复登录超时，已上线；完成导出接口，还没联调；下周联调。

以下为按“已完成、进行中、下周计划”结构整理的**示意**，实际内容和结构会随输入及所选模板变化：

| 栏目 | 整理后的内容 |
| --- | --- |
| 已完成 | 修复登录超时问题，已上线。 |
| 进行中 | 导出接口开发完成，尚未联调。 |
| 下周计划 | 进行导出接口联调。 |

整理的目标是分类、合并重复信息和理顺措辞。确认初稿时，再检查事实和进展是否准确，补上需要交代的细节。

### 按你的汇报习惯整理

有的周报按项目写，有的分成“本周进展、遇到的问题、下周计划”。你可以手动搭建模板，也可以上传几份已有的汇报样例，让 AI 归纳结构，再调整并保存，供后续周报复用。

模板用于组织汇报内容，不承诺完整复刻样例文档的字体、页眉或复杂排版。

### 初稿之后，继续改到合适

生成初稿后，可以在对话里继续提要求，例如“把这段缩短一些”，或补充明确的新进展：“导出接口已联调通过，把这个结果补进周报。”

每周可以保存多个版本。确认内容后导出 DOCX，继续在 Word 中编辑，或用于提交汇报。

## 更多输入方式与输出

- **附件作为材料**：支持上传 Word、PPT、PDF、Excel、Markdown、图片和 ZIP 等附件，提取其中的内容用于整理。
- **语音录入**：可选接入火山引擎 SAUC，把口述内容作为输入。
- **技术总结**：除了工作汇报，也能整理笔记中的技术主题、要点和参考资料。

## 本地运行

需要 Python 3.12 和 DeepSeek API key。以下命令适用于 macOS / Linux：

~~~bash
git clone https://github.com/liiiyiiixiii/weeknote.git
cd weeknote/backend

python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

cp .env.example .env
~~~

打开当前 `backend` 目录下的 `.env`，填入 DeepSeek API key：

~~~dotenv
DEEPSEEK_API_KEY=your_key_here
~~~

启动服务：

~~~bash
uvicorn app.main:app --reload --port 8000
~~~

然后访问 <http://127.0.0.1:8000>。

图片 OCR 依赖 Tesseract；如果要识别中文图片，需要额外安装 `chi_sim` 语言包。不使用 OCR 时可以忽略。

其他设置，包括数据库位置、调用限额、数据保留时间和语音识别，都写在 [backend/.env.example](backend/.env.example) 里。

## 部署

[部署文档](deploy/README.md) 提供通用的 Nginx 和 systemd 示例，使用的是 `example.com` 和 `/opt/weeknote` 等占位值。复制后替换自己的域名和路径，并按文档设置生产环境、固定应用密钥、`APP_PUBLIC_ORIGIN` 和 `ALLOWED_HOSTS`。不要把填写后的生产配置提交到仓库。

## 数据和隐私

应用没有账号系统。周报、设置和模板保存在部署机器的 SQLite 中。附件原文件不会写入数据库，但提取出的文字和未完成的会话会短暂保存，以便刷新页面或服务运行多个进程时继续处理。

整理内容会发送给你配置的 DeepSeek 服务；启用语音后，音频会发送给火山引擎。不要用它处理不允许交给第三方服务的数据。

仓库的 `.gitignore` 已包含本地 `.env`、数据库及生产配置的忽略规则；自行新增配置文件时，也请避免提交密钥或真实业务数据。
